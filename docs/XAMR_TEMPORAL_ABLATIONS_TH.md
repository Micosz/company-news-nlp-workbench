# แผนทดลองกฎเวลาในการจัดกลุ่ม X-AMR

กำหนดชุดทดลองก่อนรัน ใช้เฉพาะ Ann1 dev และ Ann2 dev ของผู้เขียน ชุดละ 1,245 mentions โดยรันแต่ละชุดแยกกันและตรึงกราฟ OR เดิม เปรียบเทียบ CoNLL F1, Pair P/R/F1, FP/FN, จำนวนวันที่ที่ใช้ได้ และจำนวนการระงับหรือตัดเส้น ใช้ gold สำหรับวัดผลและจัดกลุ่มข้อผิดพลาดภายหลังเท่านั้น

| วิธี | กฎที่ตรึงก่อนรัน | ที่มาของแนวคิด |
|---|---|---|
| OR | Connected components ของ EID_N ∪ EID_lt | X-AMR §4.2 |
| Temporal 0 | ระงับการรวมเมื่อพบคู่ข้ามกลุ่มที่เวลาห่างเกิน 0 วัน | baseline โครงงาน |
| Date Evidence | Temporal 0 กับวันที่ระดับวันที่มีหลักฐานในประโยค | baseline โครงงาน |
| Header Mask | Temporal 0 แต่เว้นวันที่ที่ตรงกับตัวเลือกจากหัวข่าวและไม่มีหลักฐานวันเดียวกันในประโยค ส่วนวันที่อื่นใช้ตาม argT | Bugert et al. §5.3.2 และภาคผนวก C/F แยกวันที่เผยแพร่กับวันที่จากบริบทในฟีเจอร์ความห่างของเวลา กฎการเว้นเป็นของโครงงาน |
| Gap 3 | Temporal ระดับกลุ่ม ยอมให้ช่วงห่างได้ถึง 3 วัน | Bugert et al. ภาคผนวก C ใช้ระยะห่างหลายหน่วย เกณฑ์ 3 วันเป็นการทดลองตอบข้อสังเกตบน dev ของเรา |
| Header Mask + Gap 3 | ใช้สองกฎพร้อมกันเพื่อดูผลร่วม | ablation แบบ 2×2 ของโครงงาน |
| Edge Only | ตัดเฉพาะเส้น OR ที่ปลายทั้งสองมีช่วงห่างเกิน 0 วัน แล้วหา connected components ตามเดิม | X-AMR §4.2 สำหรับ connected components และ CohTP §3–4 สำหรับการใช้ความสัมพันธ์เวลาบนกราฟ กฎตัดเส้นเป็นของโครงงาน |

อ่าน [X-AMR](https://aclanthology.org/2024.lrec-main.920.pdf), [Bugert et al.](https://aclanthology.org/2021.cl-3.18.pdf) และ [CohTP](https://aclanthology.org/2026.acl-long.1345.pdf) โดย X-AMR ใช้คำกำกับเหตุการณ์ประกอบการสร้าง EID ขณะที่ Bugert et al. ใช้ฟีเจอร์เวลาในตัวจำแนกหลายฟีเจอร์และพบว่าน้ำหนักของฟีเจอร์เปลี่ยนตาม corpus อีกทั้งวันเผยแพร่ของ ECB+ มีไม่ครบ CohTP ใช้ BERT-NLI, EA-GNN และขั้นจัดการข้อขัดแย้งรวมถึงการกู้ coreference ข้ามช่วงเวลา การทดลองนี้ใช้เพียงกฎวันที่บนกราฟ X-AMR ไม่มีการฝึก NLI หรือ GNN และ Edge Only ยังอาจเชื่อมคู่วันที่ต่างกันผ่านเส้นทางอ้อม

**เกณฑ์หยุด** รัน matrix ครบครั้งเดียวบนทั้งสองชุด ตรวจความตรงกันของ baseline และตรวจว่าผลที่ดูดีเป็นการเพิ่มบนทั้งสองชุดหรือเป็น tradeoff หากวิธีซ้ำผลเดิมหรือช่วยด้านหนึ่งโดยแลกกับอีกด้าน ให้บันทึกและหยุดก่อนลอง threshold เพิ่ม หากมีวิธีชนะทั้งสองชุด ให้รายงานเป็นผู้สมัครสำหรับการประเมินใหม่เท่านั้น ชุดนี้เคยใช้ดูข้อผิดพลาด จึงมีความเสี่ยง dev overfitting และ `test_common` เคยเปิดดูแล้ว

## การตัดสินใจหลังรัน

ใน matrix นี้ไม่มีวิธีใหม่ที่เพิ่มผลทั้งสองชุดเมื่อเทียบกับ OR และไม่มีวิธีที่ชนะสามตัวอ้างอิงบนทั้งสองชุด Ann1 ได้ CoNLL F1 และ Pair F1 สูงสุดที่ Temporal 0 ส่วน Ann2 ได้ CoNLL F1 สูงสุดที่ OR ขณะที่ Pair F1 สูงสุดอยู่ที่ Header Mask + Gap 3 (68.6724% เทียบกับ OR 68.4362%) และ CoNLL F1 ต่ำกว่า OR ผลต่างจึงขึ้นกับ metric ที่เลือกและวิธีแบ่งกลุ่ม ไม่ได้เลือกเปลี่ยน baseline หรือไล่หา threshold เพิ่มจาก dev

งานที่ยังไม่ได้ทำคือการตรวจตัวอย่างแบบสุ่มแบ่งตามกลุ่มข้อผิดพลาดด้วยคนแยกสามประเภท ได้แก่ วันเผยแพร่ วันเกิดเหตุ และวันสัมพันธ์กับเหตุการณ์อื่น จากนั้นจึงประเมินการจับคู่วันที่กับเหตุการณ์โดยตรง และถ้าจะวัดผลรวม ให้ล็อกกฎก่อนประเมินบนชุดที่ไม่เคยใช้ปรับวิธี

## ทำซ้ำ

```sh
.venv-xamr/bin/python xamr_lab/temporal_ablations.py --dataset ann1-dev
.venv-xamr/bin/python xamr_lab/temporal_ablations.py --dataset ann2-dev
(cd xamr_lab && ../.venv-xamr/bin/python -m unittest -q test_engine test_cloud test_date_evidence test_temporal_ablations)
```

แต่ละรอบเก็บใน `xamr_lab/runs/temporal-ablations/<dataset>/<run_id>/` มี `config.json` พร้อม checksum ของชุดข้อมูลและซอร์ส รวมทั้ง commit ของโค้ดที่ใช้จริง, `environment.txt`, `report.json` พร้อมเวลาสร้างกราฟและคัดหลักฐาน, `metrics.csv` พร้อมเวลาจัดกลุ่ม, `predictions.csv`, `vetoes.csv` พร้อมคู่พยาน และไฟล์ `error_*_vs_temporal.csv` กฎ deterministic จึงบันทึก seed เป็น null ตรวจแล้วว่าผลราย mention ของ baseline ทั้งสามตรงกับรอบเดิม ผลรันซ้ำมีคะแนน การจัดกลุ่ม และไฟล์ตรวจหลักฐานตรงกัน โดยเวลารันเปลี่ยนได้
