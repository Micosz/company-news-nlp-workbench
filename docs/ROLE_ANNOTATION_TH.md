# ทำป้ายกำกับผู้ซื้อและบริษัทเป้าหมายสำหรับ Pilot

เป้าหมายคือเตรียมข้อมูล **ที่คนอ่านและตรวจหลักฐานจริง** สำหรับทดลองว่า role features ช่วยจำแนกคู่ข้อความหรือไม่ สคริปต์นี้ไม่สกัดชื่อบริษัทอัตโนมัติ ไม่เติมคำตอบแทนผู้ทำป้ายกำกับ และไม่สร้างผลการทดลอง

## 1. สร้างแบบฟอร์ม

จากเว็บส่วน 01 กด “เตรียมและใช้ข้อมูลบทบาทผู้ซื้อ–เป้าหมาย (Pilot)” แล้วดาวน์โหลดแบบฟอร์ม หรือเปิด Terminal ในโฟลเดอร์โครงการ (ใช้ Python ของ environment ที่ติดตั้ง dependencies แล้ว):

```sh
.venv/bin/python scripts/annotate_roles.py export --output local_data/roles_pilot.xlsx
```

แบบฟอร์มมี **42 แถว เป็น 42 event mentions** หนึ่งแถวต่อข้อความ (ไม่ใช่ 424 คู่) ช่อง buyer/target เริ่มว่าง ข้อมูลอยู่ใน `local_data/` ซึ่ง Git ไม่ติดตาม ควรเก็บสำเนาที่เสร็จแล้วและบันทึกเวอร์ชัน/ผู้ตรวจแยกไว้

สคริปต์จะไม่เขียนทับไฟล์เดิม ถ้าไฟล์ปลายทางมีแล้วให้เปลี่ยนชื่อไฟล์ปลายทางใหม่ ไม่ต้องแก้ไข `mention_id` หรือ `context` ในแบบฟอร์ม

## 2. อ่านและเติมแบบฟอร์ม

| ช่อง | วิธีกรอก |
|---|---|
| `mention_id`, `context` | รหัสและบริบทที่เตรียมให้ อ่านเป็นหลักฐานและคงข้อความเดิม |
| `buyer` | ชื่อมาตรฐานของบริษัทผู้ซื้อในเหตุการณ์ หากระบุได้จาก context |
| `buyer_evidence` | คัดข้อความใน context ที่สนับสนุนการระบุผู้ซื้อ |
| `target` | ชื่อมาตรฐานของบริษัทเป้าหมาย หากระบุได้จาก context |
| `target_evidence` | คัดข้อความใน context ที่สนับสนุนการระบุบริษัทเป้าหมาย |
| `annotator` | ระบุชื่อหรือรหัสผู้ทำป้ายกำกับเมื่อกรอก role |
| `notes` | บันทึกความกำกวมหรือข้อมูลที่ต้องตรวจต่อ |

หากไม่ทราบ ให้ **เว้นช่อง role และ evidence ว่าง** อย่าใส่คำว่า `unknown`, `null` หรือเดาจาก topic, ชื่อไฟล์, gold event cluster หรือจากว่าควรทายคู่ให้ถูก ถ้าใน context ไม่พอระบุบทบาท ให้เว้นว่างแม้จะรู้ชื่อดีลจากแหล่งอื่น

หลักฐานต้องเป็นข้อความที่มีอยู่ใน `context` จริง: สคริปต์ตรวจข้อความตรงกันหลังรวมช่องว่าง/ปรับ Unicode และไม่สนตัวพิมพ์เล็ก–ใหญ่ แต่ **การผ่านตัวตรวจไม่ได้ยืนยันว่ามนุษย์ตีความบทบาทถูก** ควรให้เพื่อนตรวจซ้ำ ตัวสะกดชื่อบริษัทให้สอดคล้องกันในทุกแถว เพราะโมเดลปัจจุบันไม่ได้เชื่อมชื่อย่อและชื่อเต็มให้เอง

## 3. สร้างไฟล์คู่สำหรับรัน

บนเว็บส่วน 01 เลือกแบบฟอร์มที่กรอกแล้ว เลือก Pilot A หรือ B แล้วกด “โหลดบทบาทลงข้อมูล” ระบบจะตรวจหลักฐานและสร้างคู่ให้ เลือกที่มาของบทบาทในส่วน 02 ตามวิธีทำจริง (คนกรอก หรือโมเดลทำนาย) ก่อนรันและตรวจ coverage

หรือบันทึกไฟล์ที่ทำป้ายกำกับเสร็จ แล้วใช้ CLI:

```sh
.venv/bin/python scripts/annotate_roles.py apply --input local_data/roles_pilot.xlsx --fold A --output local_data/pilot_A_manual_roles.xlsx
.venv/bin/python scripts/annotate_roles.py apply --input local_data/roles_pilot.xlsx --fold B --output local_data/pilot_B_manual_roles.xlsx
```

แต่ละไฟล์มี 424 คู่ พร้อม `buyer_a`, `target_a`, `buyer_b`, `target_b` และคง labels กับการแบ่ง train/test เดิมไว้ สคริปต์รายงานจำนวนคู่ที่รู้ทั้งสองบทบาทครบในแต่ละ split ซึ่งเป็น **coverage ของข้อมูลที่ป้อน** ไม่ใช่คะแนนความถูกต้องของโมเดล

นำไฟล์คู่ที่ต้องการเข้าเว็บ จับคู่คอลัมน์ให้ถูก ตั้งที่มาบทบาทเป็น **คนทำป้ายกำกับ (manual/oracle)** หากคนทำและตรวจจริง หรือเลือกโมเดลทำนายหากใช้ผลจากโมเดล พร้อมบันทึกที่มาและการตรวจทานในหมายเหตุ หากยังไม่มีบทบาทครบใน train และ test โมเดลส่วนเพิ่มจะถูกข้ามตามเงื่อนไขของอัลกอริทึม และผลที่เห็นยังไม่ใช่ผลส่วนเพิ่ม

รองรับ CSV แทน Excel โดยเปลี่ยนนามสกุล `--output`/`--input` เป็น `.csv` ไฟล์ Excel อ่านเฉพาะชีตแรก

## ขอบเขตและความระมัดระวังในการสรุปผล

- คู่ same-event มี gold labels จาก ECB+ เดิม ไม่ใช่ labels ที่สร้างจากความตรงกันของผู้ซื้อ/เป้าหมาย
- Pilot มีเพียง 4 focal events ใน 2 topics และแต่ละดีลที่เลือกมีหนึ่ง focal event; target ตรงกันอาจกลายเป็นทางลัดของข้อมูลชุดนี้ แม้ทำ annotation แยกอย่างถูกต้อง ผลสูงไม่ได้แสดงว่าแยกหลายเหตุการณ์ในดีลเดียวกันได้
- หาข้อมูลเพิ่มที่ **ผู้ซื้อและเป้าหมายเดียวกัน แต่เป็นคนละเหตุการณ์** พร้อม gold ที่กำหนดอย่างอิสระ ก่อนสรุปว่าฟีเจอร์ใช้ได้ทั่วไป
- Pilot A/B เป็นการสลับข้อมูลชุดเดียวกัน ไม่ใช่ test อิสระสองชุด และ pilot ซ้อนกับหัวข้อใน full test; ถ้าใช้ผลเดิมออกแบบโมเดล ควรเตรียม held-out ใหม่ก่อนสรุปสุดท้าย
- ป้ายกำกับ manual เป็นการทดลองเมื่อ **ให้ข้อมูลบทบาทที่คนทำแล้ว** ยังไม่ประเมินความสามารถของระบบสกัดบทบาทอัตโนมัติ
