# ทดลองตรวจหลักฐาน ARG1 จากต้นฉบับข่าวก่อนตัดเส้น

## แผนก่อนรัน

[Pietrantuono et al., Schema-Constrained Document-Level Event Argument Extraction](https://arxiv.org/abs/2607.16808) เผยแพร่ arXiv v1 วันที่ 18 กรกฎาคม 2026 ไม่พบฉบับชื่อเดียวกันก่อนปี 2026 ในการค้น งานต้นฉบับ §3 ใช้ schema ต่อประเภทเหตุการณ์, LoRA บนโมเดล 8–14B และตรวจ JSON, role และ span กับหน้าต่างข้อความก่อนวัดผลบน MAVEN-ARG ข้อจำกัดสำคัญคือ span ที่พบในหน้าต่างอาจเป็นคนละ mention และผลขึ้นกับขอบเขตหน้าต่างกับการจับคู่แบบตรงตัว [บทความฉบับเต็ม](https://arxiv.org/html/2607.16808v1) · [repo MIT และเงื่อนไขข้อมูลแยก](https://github.com/dessertlab/EAE)

นำเฉพาะแนวคิดตรวจว่าข้อความสนับสนุน argument ก่อนใช้ มาเขียนกฎเองบน X-AMR ใช้ slot ARG1 ของ X-AMR และค่าที่ผู้เขียนให้มา ไม่ย้าย schema MAVEN-ARG ไม่ฝึกโมเดล ไม่คัดลอกโค้ดหรือไฟล์ของ EAE และไม่อ้างว่าสกัด argument เอง ไม่ส่งข้อมูลออกจากเครื่อง งาน [Gatti et al.](https://arxiv.org/abs/2605.10627) v1 วันที่ 11 พฤษภาคม 2026 เป็นกรอบวิเคราะห์ entity coreference; รอบนี้แยกชนิดข้อผิดพลาดเพื่ออธิบายผลและไม่ได้ใช้เครื่องมือหรือคะแนนของ paper นั้น

- ตรึงกราฟและป้ายเดิมบน Ann1/Ann2 dev เปรียบเทียบ OR, Temporal 0 และ ARG1 Guard เดิม รันใหม่พร้อมสองวิธีที่เพิ่ม โดยให้ gold เข้าถึงเฉพาะตอนวัดผล
- ใช้เฉพาะเส้นที่ ARG1 Guard เดิมจะตัด (EID_lt อย่างเดียว, ARG1 ทั้งสองด้านเป็นข้อความและไม่ตรงกัน) **Document Alignment** ตัดเมื่อพบ ARG1 ที่ระบุไว้เต็มคำในเนื้อเอกสารทั้งสองด้าน โดยข้ามบล็อก URL **Sentence Alignment** ใช้กฎเดียวกันในประโยค mention ของแต่ละด้าน ไม่ผ่านหลักฐานให้คงขอบ OR และนับ coverage แยก ไม่มีการแก้ข้อมูลเดิม ไม่เปลี่ยน EID_N หรือ tolerance
- ยึดการเปรียบเทียบเดิมที่แบ่ง ARG1 หลายค่าด้วย slash ค่าที่เป็น roleset ซ้อนหรือว่างจะไม่ถูกใช้ตัดเส้น ตรวจตัวอักษรด้วย token ต่อเนื่องหลัง normalization เดียวกันทั้งสองด้าน การพบคำในข้อความเป็นหลักฐานว่าข้อความมีค่านั้น แต่ยังไม่ได้พิสูจน์บทบาทหรือว่าชื่อต่างกันหมายถึงคนละคน
- วัด CoNLL F1, Pair P/R/F1, FP/FN, coverage, เส้นที่ตัด และคู่ที่เปลี่ยนเทียบ OR ใช้ dev ชุดเดิมเพื่อสำรวจและตรวจทำซ้ำหนึ่งรอบ หลังรันคู่หน้าต่างที่ตรึงไว้และตรวจผลทั้งสองชุดแล้วให้หยุดการปรับกฎ หากผลไม่ชนะทั้งสอง ให้ตรวจว่าข้อจำกัดอยู่ที่ span coverage หรือการระบุตัวตน โดยไม่ไล่เกณฑ์เพิ่มและไม่เปิด test_common

## ทางเลือกและเกณฑ์หยุด

ตรวจ [ImCoref-CeS v1](https://arxiv.org/abs/2510.10241v1) แล้วลงครั้งแรกวันที่ **11 ตุลาคม 2025** แม้ฉบับ ACL อยู่ปี 2026 จึงตัดออกตามเงื่อนไขปีเผยแพร่ รอบนี้หยุดหลังเปรียบเทียบสองหน้าต่างที่ตรึงไว้และเห็นว่าผลที่ดีมาจากหัวข้อเดียว หากทำต่อควรวัดว่าระบบโยงผู้เกี่ยวข้องกับบทบาทของเหตุการณ์ได้จริงก่อนนำไปตัดเส้น ต้องมีตัวอย่าง span และบทบาทที่ตรวจอิสระ ซึ่ง benchmark รอบนี้ยังไม่ได้จัดทำ

## ทำซ้ำ

```sh
.venv-xamr/bin/python xamr_lab/source_aligned_arguments.py --dataset ann1-dev
.venv-xamr/bin/python xamr_lab/source_aligned_arguments.py --dataset ann2-dev
(cd xamr_lab && ../.venv-xamr/bin/python -m unittest -q test_engine test_cloud test_date_evidence test_temporal_ablations test_cross_time_recovery test_source_aligned_arguments)
```

ผลอยู่ใน `xamr_lab/runs/source-aligned-arguments/` รอบ Ann1 `20261115T143419-91e2fad0` และ Ann2 `20261115T143419-4679c880` มี config, data/source checksum, seed (null), metrics, predictions, หลักฐานราย mention, เส้นที่ตัด และคู่ที่เปลี่ยน ตรวจแล้วว่า baseline ทั้งสามให้คลัสเตอร์ตรงกับรอบก่อน รันซ้ำแล้ว CSV/config ตรงกันและผ่าน 26 tests เวลา inference ประมาณ 0.42–0.45 วินาทีต่อชุดบน CPU ของเครื่องนี้ รวมสร้างกราฟและการจัดกลุ่มทั้งห้าวิธี แยกจากการโหลดข้อมูลและคำนวณคะแนน ไม่ใช้ API และไม่ดาวน์โหลดโมเดลเพิ่ม
