# ทดสอบนัยสำคัญของผลต่างเทียบกับ OR

ผลใน `metrics.csv` บอกว่า OR+TF-IDF ได้ Pair F1 ต่ำกว่า OR ราว 3–4 จุด แต่ชุด dev มีเพียง 8 หัวข้อ
และส่วนต่างส่วนใหญ่มาจากหัวข้อเดียว (หัวข้อ 35 ดู `XAMR_TOPIC_ANALYSIS_TH.md`)
คำถามของเอกสารนี้คือ ส่วนต่างระดับนี้แยกออกจากความบังเอิญของการที่หัวข้อชุดนี้ถูกเลือกมาได้หรือไม่

## ทำไมใช้หัวข้อเป็นหน่วย

mention ในหัวข้อเดียวกันพูดถึงเหตุการณ์ชุดเดียวกัน ความผิดพลาดจึงเกิดพร้อมกันเป็นกลุ่ม
ถ้าสุ่มทีละ mention จะเหมือนมีข้อมูลอิสระ 1,245 ชิ้น ซึ่งทำให้ช่วงความเชื่อมั่นแคบเกินจริง
ทุกการทดสอบในไฟล์ `significance.py` จึงสุ่มหรือสลับทีละหัวข้อ แล้วรวม TP/FP/FN (หรือผลรวม B³) ของหัวข้อที่ได้ก่อนคิดคะแนน

## สองวิธีที่ใช้

**Paired bootstrap (ช่วงความเชื่อมั่น 95%)**
สุ่มหัวข้อแบบใส่คืนให้ได้ 8 หัวข้อ แล้วคิดคะแนนของทั้งสองระบบบนชุดเดียวกัน ทำ 1,000 รอบ (seed 374)
ช่วง 95% คือ percentile ที่ 2.5 และ 97.5 ของส่วนต่าง ถ้าช่วงข้ามศูนย์ แปลว่ายังบอกทิศทางไม่ได้

**Permutation test แบบสลับรายหัวข้อ (ค่า p)**
ถ้าสองระบบเก่งเท่ากัน การสลับผลของสองระบบในหัวข้อใดก็ไม่ควรทำให้ส่วนต่างเปลี่ยนมาก
8 หัวข้อมีวิธีสลับ 2⁸ = 256 แบบ และลองครบทุกแบบโดยไม่สุ่ม
ค่า p คือสัดส่วนของแบบที่ได้ส่วนต่าง (ค่าสัมบูรณ์) ไม่น้อยกว่าที่เห็นจริง เป็นการทดสอบสองทาง

สองวิธีใช้หลักคิดต่างกัน ถ้าสรุปตรงกันจะมั่นใจในข้อสรุปได้มากขึ้น

## วิธีใช้

รันจากโฟลเดอร์ `xamr_lab`

```sh
python analyze.py significance runs/<run_id>
python analyze.py significance runs/<run_id> --method OR_TFIDF --rounds 2000 --seed 1
```

คำสั่งพิมพ์ตารางบนหน้าจอและเขียน 2 ไฟล์ไว้ในโฟลเดอร์ run

- `significance.csv`: `method`, `baseline`, `metric` (`pair_F1` หรือ `B3_F1`), `delta` (หน่วยเป็นจุด %),
  `ci_low`, `ci_high`, `p_value`, `topics`, `rounds`, `seed`
- `significance.md`: ตารางเดียวกันพร้อมคำอ่านผล `better`, `worse` หรือ `no clear difference` (เกณฑ์ p < 0.05)

## อ่านผลอย่างไร

- **`worse` หรือ `better`**: ส่วนต่างเกิดซ้ำในหลายหัวข้อพอที่จะไม่ใช่ความบังเอิญ เช่น TF-IDF อย่างเดียวเทียบกับ OR
- **`no clear difference`**: ไม่ได้แปลว่าสองระบบเท่ากัน แปลว่าข้อมูลชุดนี้ยังแยกไม่ออก
  เช่น ส่วนต่างมาจากหัวข้อเดียว ถ้าสุ่มได้ชุดที่ไม่มีหัวข้อนั้น ส่วนต่างก็แทบหายไป
- ส่วนต่างที่เป็น 0 พอดีทั้งช่วงและ p = 1 แปลว่าสองระบบให้กลุ่มเหมือนกันทุก mention (เช่น OR+TF-IDF+NB)

## ข้อจำกัด

- **มีเพียง 8 หัวข้อ** ค่า p ที่เล็กที่สุดที่เป็นไปได้คือ 2/256 ≈ 0.0078 และ bootstrap ที่มีหน่วยน้อยมักให้ช่วงแคบกว่าความจริงเล็กน้อย
  จึงควรอ่านคู่กับ permutation test ไม่ใช่อ่านช่วงอย่างเดียว
- ไม่ได้ปรับค่า p สำหรับการทดสอบหลายครั้ง (หลายวิธี × 2 ตัววัด) หากต้องการเข้มขึ้น ให้ใช้เกณฑ์ 0.05 หารด้วยจำนวนการทดสอบ
- ไม่ได้ทดสอบ MUC, CEAF_e และ CoNLL F1 เพราะยังไม่ได้คำนวณรายหัวข้อแบบรวมกลับได้ ใช้ Pair F1 และ B³ แทน
- ผลนี้ใช้ dev เท่านั้น ไม่ได้เปิด `test_common` ตามโปรโตคอลเดิมของงาน

## Test

```sh
python -m unittest test_significance test_analyze
```

`test_significance.py` ตรวจการสุ่มซ้ำได้, percentile, กรณีระบบเหมือนกัน (p = 1, ช่วง [0, 0])
และกรณีที่รู้คำตอบ เช่น แย่กว่าทุกหัวข้อต้องได้ p ต่ำสุด แต่แย่กว่าหัวข้อเดียวต้องไม่มีนัยสำคัญ
