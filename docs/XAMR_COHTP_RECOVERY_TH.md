# ทดลองคืนเส้นเชื่อมข้ามเวลาให้ X-AMR

## ที่มาและแผนที่ตรึงก่อนรัน

ใช้ [CohTP ของ Chen et al.](https://aclanthology.org/2026.acl-long.1345/) ตีพิมพ์ ACL เดือนกรกฎาคม 2026 เป็นฐานแนวคิดใหม่ การค้นชื่อเต็ม รวมถึงชื่อผู้เขียนกับคำว่า arXiv, OpenReview และ preprint พบฉบับ ACL ปี 2026 เป็นฉบับสาธารณะที่ตรวจยืนยันได้และไม่พบฉบับก่อนปี 2026 การค้นนี้ยืนยันได้เฉพาะแหล่งที่พบ [repository ผู้เขียน](https://github.com/chenxinyu-nlp/CohTP) ยังมีเพียง placeholder และไม่พบ license ของ implementation ในรายการไฟล์ จึงเขียนโค้ดเองและไม่ใช้ข้อความ รูป โค้ด หรือโมเดลของ paper เป็นอินพุต ใช้เฉพาะชุดเดิมและ engine X-AMR ที่มี [Apache 2.0 สำหรับโค้ด vendored](../xamr_lab/vendor/LICENSE) และ [ข้อกำหนดแหล่งข้อมูล](../xamr_lab/NOTICE.md) ตามเดิม

CohTP §4.1 แยกเวลาแล้วตรวจแก้เฉพาะความสัมพันธ์ BEFORE ที่น่าสงสัยด้วยโมเดล ส่วน §4.2 ใช้บริบทข้างเคียงตามช่วงเวลาเพื่อช่วยตัดสินคู่ และ §3.4 จัดการความขัดแย้งของกราฟ ผู้เขียนระบุข้อจำกัดเรื่องการพึ่งคำทำนายเวลา การแบ่งช่วง และ mentions ที่มีอยู่แล้ว งานนี้ยืมเฉพาะลำดับ **กั้นก่อน แล้วทบทวนคู่ที่ถูกกั้นด้วยหลักฐานข้อความ** โดยไม่เลือกตัวอย่างจากคะแนน MAVEN-ERE test ไม่ใช้ BERT-NLI, GNN, Longformer หรือ GPT-4 และไม่ใช่การทำซ้ำ CohTP

[uCDCR](https://arxiv.org/abs/2603.00621) มี v1 วันที่ 28 ก.พ. 2026 และเน้นการรวมชุดข้อมูลกับการประเมิน ใช้ประกอบความเข้าใจเรื่อง benchmark เท่านั้น ในรอบนี้ไม่เพิ่มชุดข้อมูล

### เงื่อนไข

1. รันบน Ann1 dev และ Ann2 dev ต้นฉบับชุดเดิม ใช้ OR และ Temporal 0 เดิม พร้อม Date Evidence เดิมเป็นตัวเทียบ ใช้ gold หลัง inference เท่านั้น
2. เริ่มจากกลุ่มของ Temporal 0 พิจารณาเฉพาะขอบ OR ที่ถูกระงับโดยตรงและยังข้ามกลุ่มสุดท้าย ปลายทั้งสองต้องเป็นคนละเอกสาร มีวันขัดกันที่ tolerance 0 และอย่างน้อยด้านหนึ่งมีวันที่ตรงกับหัวข่าวตามกฎเดิม ตรวจว่า lemma และ roleset ตรงกัน
3. **Sentence Recovery** คืนขอบเมื่อประโยค mention ที่คงตำแหน่ง trigger ไว้ตรงกันหลัง normalize และมีคำอื่นนอก trigger
4. **Context Recovery** เพิ่มกรณีที่ trigger ตรงกันและข้อความประโยคติดกันด้านก่อนหรือด้านหลังตรงกันอย่างน้อยหนึ่งด้าน กรณีที่บริบทรอบข้างถูกแยกผิดหรือไม่มีประโยคที่หาได้ให้ใช้เฉพาะกฎ Sentence ตัดหัวข่าววันที่/URL จากข้อความข้างเคียง
5. รวมกลุ่มหนึ่งรอบเฉพาะเมื่อทั้งสองกลุ่มเสนอได้เพียงคู่เดียวและเลือกตรงกัน ป้องกันการรวมเป็นสายโซ่ในรอบนี้ เงื่อนไขนี้เป็นของโครงงาน ทดลองสองแบบโดยแยกจากกัน
6. วัด CoNLL F1, Pair P/R/F1, FP/FN, จำนวนคู่พิจารณาและการรวมจริง ไม่มีค่าที่ต้องฝึกหรือปรับ ถ้าสัญญาณไม่พอหรือเป็น tradeoff ให้จบรอบโดยไม่ผ่อนเกณฑ์เพื่อไล่คะแนน ถ้าพบวิธีดีขึ้น ให้ตรวจความเสถียรด้วย replay และเทียบราย topic ก่อนพิจารณาประเมินภายนอก ไม่ใช้ `test_common` ที่เคยเปิดผลแล้ว

Ann2 แบบเพิ่มบริบทกู้คืน 59 จาก 76 คู่ในหัวข้อ 35 ที่เกี่ยวกับข่าวจับนักกีฬา อีก 13 คู่มาจากหัวข้อ 23 และ 4 คู่จากหัวข้อ 12 คู่รวมผิดทั้ง 4 อยู่ในหัวข้อ 23 ตัวอย่างคู่เรือ INS Sukanya `12_6ecbplus.xml_6` และ `12_9ecbplus.xml_5` มีประโยคตรงกันที่กล่าวถึงการโจมตี 10 พ.ย. แต่มี argT 15 และ 11 พ.ย. 2011 จึงกู้คืนได้ ส่วน `23_2ecbplus.xml_26` กับ `23_3ecbplus.xml_13` เป็นตัวอย่างรวมผิดหลังการคืนเส้น อีกฝั่งกล่าวถึงนักปีนเขาคนเดียว ขณะที่พาดหัวกล่าวถึงสองคน แม้กฎตรวจหลักฐานที่ปลายเส้น ผลจากการรวมกลุ่มอาจขยายไปถึง mention อื่นที่ไม่ได้ตรวจเป็นรายคู่

ผล Ann2 ดีขึ้นจาก Temporal 0 แต่ยังต่ำกว่า OR และวิธี Header Mask + Gap 3 ของรอบก่อนบนทั้ง CoNLL/Pair F1 (76.88%/68.67%) ส่วน Ann1 คงผล Temporal เดิม การกู้คืนกระจุกในหัวข้อเดียวและอาศัยถ้อยคำตรงกัน ซึ่งอาจเป็นข่าวที่ใช้ต้นฉบับเดียวกัน จึงหยุดตามเกณฑ์ก่อนผ่อนกฎ ความเป็นไปได้ถัดไปคือทดสอบการกู้คืนกับข้อความที่เขียนใหม่และใช้ชุดประเมินใหม่ที่มีการตรวจที่มาของวัน ยังไม่ได้ทดสอบขั้นนั้น

### ทำซ้ำและตรวจหลักฐาน

```sh
.venv-xamr/bin/python xamr_lab/cross_time_recovery.py --dataset ann1-dev
.venv-xamr/bin/python xamr_lab/cross_time_recovery.py --dataset ann2-dev
(cd xamr_lab && ../.venv-xamr/bin/python -m unittest -q test_engine test_cloud test_date_evidence test_temporal_ablations test_cross_time_recovery)
```

ผลอยู่ใน `xamr_lab/runs/cross-time-recovery/` รอบ Ann1 `20261115T141522-cd0cb8b6` และ Ann2 `20261115T141522-c763cec9` มี config, source/data SHA-256, scores, predictions, คู่ที่พิจารณาและคืนเส้น, ผลรายหัวข้อ, และเวลา inference รันซ้ำได้ CSV/config ตรงกันทุกไฟล์ เวลา inference ของรอบแรกอยู่ที่ 0.22–0.23 วินาทีต่อชุดบนเครื่องนี้ รวมการสร้างกราฟและจัดกลุ่ม ไม่รวมโหลดข้อมูลและคำนวณคะแนน ใช้ dependency เดิมบน CPU ไม่มี API และ seed เป็น null เพราะไม่มีขั้นสุ่ม
