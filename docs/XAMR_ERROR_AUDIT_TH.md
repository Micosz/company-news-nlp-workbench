# ตรวจข้อผิดพลาดของวันที่และทดลองใช้ผู้เกี่ยวข้องในเหตุการณ์

## แผนก่อนเปิดตัวอย่างและรันคะแนน

สุ่มจากคู่ที่ OR และ Temporal 0 ให้ผลต่างกันบน Ann1/Ann2 dev เท่านั้น แบ่งตามชุดข้อมูล ประเภทผลต่าง (คู่เหตุการณ์เดียวกันที่ Temporal แยกผิด หรือคู่ต่างเหตุการณ์ที่ Temporal แยกถูก) และชนิดหลักฐานสามกลุ่ม (มีวันตรงหัวข่าวอย่างน้อยหนึ่งด้าน, ไม่มีหัวข่าวและห่าง 1–3 วัน, ไม่มีหัวข่าวและเป็นกรณีอื่น) เลือกหนึ่งคู่ต่อช่องที่มีข้อมูลด้วยค่า SHA-256 ต่ำสุดจาก seed 20261115 และรหัสคู่ที่เรียงคงที่ อ่านแต่ละ mention แยกกันและบันทึกหลักฐานเท่าที่จำเป็น ใช้ผู้ช่วย AI ตรวจเบื้องต้นพร้อมระดับความมั่นใจ ผลไม่ใช่คำกำกับมนุษย์ และใช้บอกลักษณะข้อผิดพลาดที่พบในตัวอย่าง

ทดสอบกฎผู้เกี่ยวข้องเพียงหนึ่งแบบ ใช้ OR เดิม ตัดเฉพาะเส้นที่มาจาก EID_lt อย่างเดียว เมื่อทั้งสองฝั่งมี ARG1 แบบข้อความ และชื่อผู้เกี่ยวข้องไม่ตรงกันหลังปรับ Unicode, case และเครื่องหมายวรรคตอน งดตัดถ้าช่องว่างหรือ ARG1 มี roleset ของเหตุการณ์ซ้อน เก็บ EID_N ทุกเส้น แล้วใช้ connected components เดิม กฎนี้ใช้ ARG1 เป็นหลักฐานเพิ่มเติมโดยไม่เพิ่มด่านวันที่จาก Temporal 0 เทียบกับ OR, Temporal 0, Date Evidence และวิธีเวลาก่อนหน้าบนทั้งสอง dev ชุดเดิม หลังรันและตรวจทำซ้ำหนึ่งรอบให้หยุด ไม่มีการจูนเกณฑ์จากผล ถ้าเห็น alias หรือการเชื่อมผ่านทางอ้อมให้บันทึกเป็นข้อจำกัด

## งานที่อ่านประกอบ

- [X-AMR (2024), §4.1–4.2](https://aclanthology.org/2024.lrec-main.920.pdf) ใช้ EID_N ที่รวมโครงสร้าง argument และ EID_lt ที่มีเวลาและสถานที่ จากนั้นจัดกลุ่มด้วย connected components กฎตรวจ ARG1 บนเส้น EID_lt อย่างเดียวเป็นการดัดแปลงของงานนี้ ผู้เขียน X-AMR ยังมีการทดลอง AND/OR และ VerbNet ซึ่งเป็นคนละการตั้งค่า
- [Barhom et al. (2019), §3](https://aclanthology.org/P19-1409.pdf) ใช้ semantic roles และตัวแทนคลัสเตอร์ของผู้เกี่ยวข้องในการเรียนรู้ event/entity coreference ร่วมกัน งานนี้ยืมแนวคิดเรื่องผู้เกี่ยวข้อง โดยใช้ชื่อจากคำกำกับเดิมและกฎเปรียบเทียบข้อความ จึงมีต้นทุนต่ำ แต่จับชื่อพ้องหรือตัวแทนอย่างสรรพนามไม่ดี การทำตาม paper ต้องมีข้อมูล entity mentions, semantic role linking และการฝึกโมเดล
- [Bugert et al. (2021), §5.3, §6 และ Appendix C](https://aclanthology.org/2021.cl-3.18.pdf) ประเมินฟีเจอร์ action, บริบท TF–IDF, เวลา และผู้เกี่ยวข้องข้ามชุดข้อมูล ความสำคัญของฟีเจอร์เปลี่ยนระหว่าง corpus ส่วน TF–IDF ทำได้บน CPU แต่การใช้เป็นเกณฑ์ตัดคู่ต้องออกแบบวิธีเลือกเกณฑ์จาก train แยกต่างหาก จึงเก็บเป็นทางเลือกที่ยังไม่ได้ทดลองในรอบนี้

ผลหลักฐานในเครื่องอยู่ที่ `xamr_lab/runs/argument-audit/` โฟลเดอร์ของแต่ละชุดมี config พร้อม SHA-256 ของข้อมูล ซอร์ส และผลอ้างอิง, metrics พร้อมเวลา, predictions, รายการเส้นที่ตัด และรายการสุ่มพร้อม seed กับ hash หลักฐานเนื้อข่าวเก็บใน `sample_context_local.json` ภายในโฟลเดอร์ผลรัน รันซ้ำแล้วได้คะแนน กลุ่ม รายการสุ่ม และเส้นที่ตัดตรงกัน เวลารันเปลี่ยนได้ การสุ่มและประเมินผลใช้ gold หลัง inference ส่วนกฎจัดกลุ่มเห็นเฉพาะข้อมูลของ mentions ไม่มีการใช้ test_common เพิ่ม
